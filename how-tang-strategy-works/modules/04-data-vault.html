数据保险库

银行金库：草稿纸是 seed，总账是 SQLite，公开宣传册是 Pages。

复盘包从哪装货？

上一课：API 从库里打包。这一课：库本身怎么进货，公开静态站又读谁。

唯一运行时真相是被 Git 跟踪的 tracked SQLite。seed 只是本地抓取输入；Pages 是从同一本总账导出后再构建。

data/
seed/market-data/live_extended/ 受理窗口的临时单据（抓取输入）
sqlite/
tang_strategy_live_extended.db 金库总账 · 运行时真相
content/trades/ 规范交易原文（canonical），不是草稿
frontend/public/reviews/ 导出 JSON · 构建输入，不是真相源

进货流水线：从单据到宣传册

默认路径永远是「候选库 → 校验 → 原子晋升」。不许跳步把半成品直接当总账。

1
Seed JSON

live_extended/<date>/ 成对 SPY/QQQ 单据；本地抓取写入，不进公开站。

2
Candidate DB

重建先写候选库；日期缩水等硬门一失败就拒收。

3
Live tracked DB

校验通过后原子 promote——这才是 runtime 真相。

4
Export static JSON

从 live DB 导出 slug 文件；Pages 读的是这份拷贝，不是 seed。

5
StaticReviewsApp

静态模式挂载公开宣传册：无登录、无编辑，只浏览导出结果。

🚫
生成物不进 docs/

静态 review JSON、Vite dist、Pages 产物都不是文档。故意存档的 OPT 截图/验收钉可以跟记录走；构建输出禁止写回 docs/。

两种营业方式

同一个前端仓库，环境变量决定开「柜台」还是发「宣传册」。

CODE 
createRoot(document.getElementById('root')).render(
  import.meta.env.VITE_STATIC_REVIEWS === 'true'
    ? <StaticReviewsApp />
    : <App />,
);
白话对照

VITE_STATIC_REVIEWS=true → 只开宣传册浏览壳。

否则 → 完整交互 App（登录、API、编辑能力）。

两套壳，同一套导出/总账约定，不要混着改。

interactive 登录 + Bearer + 调 live API；可编辑/导入（视角色）
static / Pages 无登录、无写接口；只读导出 JSON + hash 选日
content/trades 交易规范原文；入库是投影，改交易先改这里
seed JSON 本地抓取输入；只改 seed 不 rebuild = 总账不变

宣传册怎么写页码

导出用确定性 slug；打开静态站时按 key / hash / 默认日解析——hash 坏了要会回落，不能空白死页。

CODE 
def slugify_day(day: dict[str, Any]) -> str:
    ticker = str(day["ticker"]).lower()
    session = str(day["session_mode"] or "session").lower().replace("_", "-")
    return f"{ticker}-{day['trade_date']}-{session}"

白话对照

slugify_day：把一天编成 spy-2026-07-17-extended 这类页码。

ticker 小写 + 日期 + session（下划线变连字符）。

resolveInitialWorkspace：先排序可用日列表。

一个交易日都没有 → kind=empty，别假装有数据。

有 explicitKey 且能匹配 → 精确打开那一天。

（后续）hash 无效会 fallback 默认日，而不是白屏卡死。

🏦
三层分清就不怕 AI 写错地方

seed = 受理单据 · SQLite = 金库总账 · Pages JSON = 宣传册复印件。改单据却不 rebuild，宣传册和柜台都还是旧账。

场景测验：数据源与回落

发布错数据，多半是把 seed、总账、宣传册搞混了。做完这三题再指挥 AI。

1. 公开 Pages 上的 SPY 复盘，数据源实际是什么？

2. 静态站 URL hash 写成不存在的日期时，合理行为是？

3. 要修正某日公开复盘上的成交点位，第一落点应是？

指挥 AI 的正确词

用 candidate、promote、export、manifest、content/trades——别说「把数据随便写进 docs 就行」。
