点开复盘

像进电影院：选好片子，胶片和字幕一起上映。

一页复盘从哪里来？

你打开 Tang Strategy，登录后点「复盘」，选一个交易日——图表和交易标记就出现了。

下面拆开这一秒里发生了什么：谁在要数据，谁在打包，谁在画图。

🎬
电影院隐喻

你选片子（标的 + 日期）；放映员把胶片（K 线）和字幕（交易点位）一起装进放映机。

🎞️
胶片 = bars

分钟级行情 K 线，从库里读出再送给画布。

💬
字幕 = 交易点

买卖标记叠在图上，让人一眼看到进出场。

🎟️
票根 = 选择

标的、交易日、策略——三者定了才开映。

用户旅程：五步到图

整条链路很短。记住顺序，排查时就不会乱枪打鸟。

1
登录

未认证时只渲染 LoginPage，进不了复盘。

2
点「复盘」

Layout 把 active 切到 review。

3
选日 + 选策略

ReviewPage 等你选好 selectedDay 和 selectedStrategy。

4
调用 assemble

前端打 API 的 /reviews/assemble，拿回一份 JSON。

5
画图

KlineEngine 把 payload 画成蜡烛图与交易点。

💡
Aha：一页 = 一次组装

屏幕上的「一页复盘」不是魔法，是后端把行情 + 策略 + 交易记录打包成一份 JSON，前端再画出来。

代码在说什么：路由切换

React 入口用 active 决定渲染哪一页——复盘只是其中一个分支。

CODE 
  if (!authenticated) return <LoginPage onLogin={() => setAuthenticated(true)} />;

  return (
    <Layout active={active} onNavigate={setActive}>
      {active === 'dashboard' && <DashboardPage state={state} setState={setState} onNavigate={setActive} />}
      {active === 'review' && <ReviewPage state={state} setState={setState} onNavigate={setActive} />}
      {active === 'backtest' && <BacktestPage state={state} setState={setState} />}
PLAIN ENGLISH

没登录？只显示登录页，别的全挡在外面。

已登录：用 Layout 包住内容，并记下当前标签。

active 是 dashboard 就渲染仪表盘页。

active 是 review 才挂上 ReviewPage——复盘从这里开始。

active 是 backtest 则挂上回测页。

当选中的日或策略变化时，跑这段副作用。

缺日或缺策略？直接退出，不发请求。

开 loading，清空旧错误，准备新请求。

用日 id 和策略 id 调用 Api.review。

成功拿到 payload 后写入 review 状态，供图表使用。

真正的 URL 写在客户端封装里——注意查询参数名字。

CODE 
export const Api = {
  tickers: () => api('/tickers'),
  marketDays: (params = {}) => api(`/market-days?${new URLSearchParams(params)}`),
  bars: (id, timeframe) => api(`/market-days/${id}/bars?timeframe=${timeframe}`),
  strategies: () => api('/strategies'),
  review: (marketDayId, strategyId) => api(`/reviews/assemble?market_day_id=${marketDayId}&strategy_id=${strategyId}`),
PLAIN ENGLISH

Api 是一小组命名好的请求助手。

tickers / marketDays / bars / strategies 各管一类列表或明细。

review 才是复盘核心：打 assemble，带上 market_day_id 与 strategy_id。

缺任一参数，后端装不齐「一页复盘」。
