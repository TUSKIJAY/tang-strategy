05

宁可失败也不乱写

空管塔台换跑道：新航班计划必须全部过检，旧跑道先备份；半空发现问题就立刻切回备份。

为什么「有一个就算了」不行？

每天都要更新 SPY + QQQ 这对标的。抓取失败、质量门没过、半路断电——这时候旧库必须完好。

核心原则叫 fail-closed ：宁可整次更新失败，也不接受「只写进一半」的生产库。

🛡
fail-closed vs fail-open

fail-closed：门没过 → 拒绝写入 → 旧 live 继续服务。
fail-open：门没过 → 硬塞进去 → 半套数据污染生产。
Tang Strategy 的日常路径永远是前者。

塔台换跑道：四步

把更新想成空管切换跑道。 candidate 是新计划，live 是正在使用的跑道，backup 是随时可切回的旧跑道副本。

1
Stage pair — 成对进场

orchestrator 要求 PAIR = ("SPY", "QQQ") 同一天、同一 provider 。只到一个标的 = 整批拒绝。

2
Validate — 硬门检查

会话模式、provider 一致、bar 质量等 hard gate 必须全过。TV 优先；IB 只在 TV 重试与硬门失败之后才作为后备。

3
Build candidate — 新跑道旁建

在旁路建好完整 candidate，并先做好 live 的 verified backup。candidate 还没 promote 前，用户仍读旧跑道。

4
Promote OR keep old — 授权落地或原路返回

锁住 live → 确认没漂移 → os.replace → fsync → post_validate 。验证失败立刻把 backup 换回 live。

成对常量：同一天、同一源

编排器写死了这对关系。日常路径禁止「只收 SPY」「混用两个 provider」「默认 --allow-date-loss」。

Code 
PAIR = ("SPY", "QQQ")
SESSION_MODE = "extended"
PROVIDERS = {"tradingview", "ibkr"}
TRADINGVIEW_EXCHANGES = {
    "SPY": "AMEX",
    "QQQ": "NASDAQ",
}
Plain English
PAIR — 永远成对：SPY 与 QQQ 同进同退
SESSION_MODE — 扩展时段会话，不是任意字符串
PROVIDERS — 只认这两个源：TV 优先，IB 后备
TRADINGVIEW_EXCHANGES — 各标的在 TV 上的交易所代码
tradingview first 日常默认源；不因 Gateway 关闭就去找 IB
ibkr fallback 仅在 TV 重试或硬门失败后，报告失败门再请开 Gateway
never --allow-date-loss 日常/默认路径禁止用丢日期换「强行通过」

promote_candidate：签名在说什么

推广不是「覆盖文件」那么简单。函数要同时拿着 live、candidate、baseline 令牌、backup 和推广后校验回调。

Code 
def promote_candidate(
    live_path: Path,
    candidate_path: Path,
    baseline_token: DatabaseToken,
    backup_path: Path,
    post_validate: Callable[[Path], None],
) -> None:
    """Compare-and-swap a verified candidate
    while preserving a verified backup."""
Plain English
live_path — 正在服务的跑道（生产 DB）
candidate_path — 已通过检查、等待授权落地的新计划
baseline_token — 开建 candidate 时的 live 快照指纹
backup_path — 已验证的旧跑道副本，失败可秒切回
post_validate — 替换后再验一次；不过就回滚
docstring — 对比并交换（CAS），同时保住 verified backup

漂移拒绝：live 在快照后被改了？

锁住写入后先检查：live 是否还是你开建 candidate 时那一份。若别人/别进程在中间改过，直接拒绝推广。

Code 
with db_write_lock(live):
    _checkpoint_and_require_quiescent(live)
    current_token = capture_database_token(live)
    if current_token != baseline_token:
        raise RuntimeError(
            "Refusing DB promotion: live DB drifted "
            "after the candidate snapshot "
            f"(baseline={baseline_token.as_dict()}, "
            f"current={current_token.as_dict()})"
        )
Plain English
db_write_lock — 独占跑道，防止双写
_checkpoint_and_require_quiescent — 要求库安静、可安全替换
capture_database_token — 抓当前 live 指纹
!= baseline_token — 和开建时不一致 → 漂移
RuntimeError — 拒绝推广，candidate 不上线

落地与回滚：一秒钟的生死线

令牌对上了，才做原子替换。替换后立刻再验；任何异常都把 backup 换回 live，再把异常抛出去。

Code 
os.replace(candidate, live)
fsync_directory(live.parent)
try:
    post_validate(live)
except Exception:
    os.replace(backup, live)
    fsync_directory(live.parent)
    raise
Plain English
os.replace(candidate, live) — 原子改名：新跑道就位
fsync_directory — 把目录改动刷盘，防断电丢名
post_validate(live) — 替换后再跑业务硬门
except — 任一失败进入回滚通道
os.replace(backup, live) — 旧跑道立刻复位
raise — 不吞错误；调用方必须看见失败
✈
塔台口令

新计划可以作废，旧跑道不能没。这就是 fail-closed 在数据库推广上的具体形状。

带走的指挥口令

🔒
禁止 --allow-date-loss（日常）

日期集合缩小 = 停下来查，不是开开关硬推。

👯
禁止单 ticker 接受

SPY 与 QQQ 同 provider、同日、同会话；只到一个就整对失败。

📡
TV 优先，IB 只在硬门之后

先报告失败的 ticker/gate，再请开 IB Gateway 重跑完整 pair。
