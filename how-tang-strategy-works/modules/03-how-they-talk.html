它们怎么对话

登录像办门禁腕带：先换通行证，再每次请求都出示。

腕带规则：没带就别进

你已经认识演员了。现在看他们怎么说话：密码换 token，请求头带上，后端才肯拼复盘包。

前端frontend 从不直接打开数据库；它只喊 API 路径。后端校验身份后，从 SQLite 拼出 bars、strategy、trade_records。

🎫
Bearer token = 门禁腕带

Authorization: Bearer <token> 不是「问候语」，是每次进门要亮的腕带。丢了腕带 = 401 Unauthorized，和「图是空的」完全不是一回事。

一次请求的生命周期

从密码到复盘 JSON，固定五步。任何一步断了，症状都不同。

1
POST /auth/login

浏览器把密码 JSON 发给后端；密码对了才换腕带。

2
存 token + role

localStorage 记下 token 和角色（admin / readonly）。

3
api() 自动贴腕带

之后每个请求头都加 Authorization: Bearer …。

4
GET /api/reviews/assemble

后端 require_readonly 验身份，再查 day / strategy / bars。

5
返回复盘包

一份 JSON 里装 1m/5m K 线、策略体、当日交易记录——前端只负责画。

代码在说什么：换腕带 + 亮腕带

login 负责办证；api() 负责每次出门都把证贴在袖口。

CODE 
export async function login(password) {
  const response = await fetch(`${API_BASE}/auth/login`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ password }),
  });
  if (!response.ok) throw new Error('Password rejected');
  const data = await response.json();
  window.localStorage.setItem(TOKEN_KEY, data.token);
  window.localStorage.setItem(ROLE_KEY, data.role);
  return data;
}
 
export async function api(path, options = {}) {
  const token = getToken();
  const response = await fetch(`${API_BASE}${path}`, {
    ...options,
    headers: {
      'Content-Type': 'application/json',
      ...(token ? { Authorization: `Bearer ${token}` } : {}),
      ...(options.headers || {}),
    },
  });
白话对照

login：拿密码去服务台换临时通行证。

密码不对 → 直接抛错，不发腕带。

成功后把 token 和 role 塞进浏览器抽屉（localStorage）。

api(path)：每次请求先摸口袋有没有 token。

有 token → 请求头写上 Bearer …，像亮腕带。

没 token → 不带 Authorization，后端大概率 401。

两种腕带颜色

密码对照用 hmac.compare_digest，对上 admin 或 readonly 之一才算身份。

admin 管理员腕带：可写导入、改内容等管理接口
readonly 只读腕带：够看复盘、拉列表；assemble 最低要求就是它
None 密码都不对 → 不发腕带，后续请求被拒
🔐
role_from_password

后端用常量时间比较密码，返回 "admin" / "readonly" / None。腕带颜色决定你能喊哪些 API——不是前端自己声明的。

assemble：把三样东西装进同一个包

有了腕带，才允许进库房打包。缺 day、缺 active strategy、或 bars 空，各自对应不同故障。

白话对照

门口先验腕带：至少 readonly，否则进不来。

查 market_days：没有这一天 → 404「Market day not found」。

查 strategies 且 active=1：没有 → 404「Strategy not found」。

拉 1 分钟 K 线，再合成 5 分钟载荷。

解析策略 JSON，按 ticker + 日期取交易记录。

前端从不自己拼库；它只消费这个打包结果。

🚫
401 / 鉴权失败

腕带没了、过期、或根本没登录——请求在打包前就被拦下。

📦
404 Strategy / Market day

身份过了，但 day 或 active strategy 对不上——包打不出来。

📉
200 但图是空的

请求成功，可 bars 没数据或渲染层吃瘪——先查库里的 bars，再查 K 线引擎。

场景测验：先分清故障层

三题都是「你看到什么症状，该先查哪一层」——不是背路径名。

1. 用户清掉 localStorage 后再点复盘，最可能先看到什么？

2. 同事能登录但只能看图，导入接口 403。你该先核对什么？

3. 网络里 assemble 返回 200，策略名也在，但 K 线区域完全空白。优先查哪条？

⚡
指挥 AI 时用对词

说「401 鉴权」/「404 strategy」/「200 但 bars 空」，AI 才不会在登录页、策略表、画图引擎三处乱打补丁。
