# 汤总训练系统 · 执行计划 v1.0

**生成日期**: 2026-04-22
**依据**: `汤总训练系统_handoff_2026-04-22.md`（DesignBlueprint v0.1）
**MVP 范围**: 第 3 章（信号A · Reject / Support MA10）全链路跑通
**总体目标**: 产出一个「阅读 + 观摩 + 练习」可运行的样板，第 3 章能完整体验。

---

## 0. 全局约束（任何任务都必须遵守）

1. **K 线引擎零改动** — 所有行为通过 `loadData / setTimeframe / setCurrentIndex / scrollTo` 四个公共 API + EventBus 事件驱动。如果发现不动引擎就做不成，先停下升级 handoff，不要偷偷改引擎。
2. **五条硬纪律落到 build_content.py** — 任何 PR 要先过 `python tools/content_build.py` 校验。
3. **draft / published 双轨** — 任何 `claude_inference` 来源的内容**必须** `status: "draft"`；published 条目必须 `source: "tang_doc§X"` 或 `real_chart_analysis Fig N`。
4. **`tutor_40` ≤ 40 字** — 超了就 build 报错，不是"尽量"。
5. **原话优先** — `tang_doc§X` 的 body_md 要与汤总秘籍 HTML 的文本节点**逐字一致**（stretch：加 diff 校验）。

## 2. 任务详情

### T1 · 创建 `content/` 目录骨架 + sources 注册表

**目标**: 为所有内容建立命名空间，把 source 字段的 id 池固定下来。

**产出**:
- `content/schema/{chapter,card,case,exercise}.schema.json` 四份 JSON Schema
- `content/{chapters,cards,cases,exercises,flagged}/` 目录（含占位 `_index.json`）
- `content/sources/tang_doc_sections.json` — §1~§16 的 id / title / HTML 锚点
- `content/sources/real_chart_figs.json` — 图 1~16 的 id / title / 原素材路径 / 对应 chapter / category

**关键动作**:
1. 读 `汤总秘籍图文版.html` 的 16 个 `<div class="ch">...` 块，提取 `ch-n / ch-t` → 写入 `tang_doc_sections.json`。示例条目：
   ```json
   { "id": "tang_doc§3", "chapter_number": "03", "title": "进场信号A — Reject / Support MA10",
     "html_file": "reference/汤总秘籍图文版.html", "html_anchor": "<!-- 03 信号A -->" }
   ```
2. 读 `src/prepare_data.py` 的 `SEED_CATEGORIES` + `real_chart_analysis.md` 的 16 个段落标题 → 写 `real_chart_figs.json`。示例条目：
   ```json
   { "id": "real_chart§Fig02", "fig_number": 2, "title": "标准空头瀑布1阶段",
     "image_path": "_archive/源素材/高清重制/02_标准空头瀑布1阶段.png_202604121004.jpeg",
     "chapter": "ch03", "category": "reject_ma10", "scenario": "bearish",
     "analysis_anchor": "real_chart_analysis.md#场景一-图2" }
   ```
3. JSON Schema 四份，字段参考 handoff §9.1，加入：required / enum（status/kind/grade）/ pattern（source 字段的三种格式 regex）。

**验收**:
- `tang_doc_sections.json` 恰好 16 项
- `real_chart_figs.json` 恰好 16 项
- 四份 schema 对本 handoff §9.1 示例对象都能 validate 通过
- 所有目录均存在，`_index.json` 是 `{ "items": [] }`

**估时**: 40 min

### T2 · 写 `tools/content_build.py` 骨架

**目标**: 把五条硬纪律代码化，让写内容时错得早、错得响。

**产出**: 单文件 Python 脚本，无第三方依赖（只用 stdlib + 可选 `jsonschema`）。

**功能**:
1. 扫描 `content/{chapters,cards,cases,exercises}/*.json`
2. 按对应 schema validate
3. 规则层校验（schema 管不到的）：
   - `source` 格式正则：`^(tang_doc§\d{1,2}|real_chart_analysis Fig \d{1,2}|claude_inference)$`
   - `source == "claude_inference"` 且 `status == "published"` → FAIL
   - `tutor_40` 字符数（中英混合按显示宽度）> 40 → FAIL
   - Exercise `grading` 必须包含三种 grade 各至少一条 → FAIL
   - Chapter `linked_*` 里引用的 id 必须实际存在 → FAIL
   - Card 的 `chapters` 里引用的 chapter id 必须存在 → FAIL
4. 产出 `dist/tang-system/content.bundle.json`：合并所有 published 的对象（draft 也带上，但加 `_status: "draft"` 标记，产品层自己过滤）
5. 给每个 flagged item 在 `content/flagged/` 留记录，build 时把对应条目 `status` 降为 draft

**CLI**:
```
python tools/content_build.py [--strict] [--bundle-only]
  --strict       任何 warning 也 fail（默认只 error fail）
  --bundle-only  跳过校验，只出 bundle（紧急发布用，正常禁用）
```

**验收**:
- 跑 `python tools/content_build.py` 在空 content/ 下成功退出，产出空 bundle
- 手动造 5 个违规案例（缺 source / claude_inference+published / tutor_41字 / 缺 wrong 档 / 坏 id 引用），每个都能被捕获并打印可读报错
- 校验器对本 handoff §9.1 的示例对象全部通过

**估时**: 50 min

### T3 · `dist/tang-system/` 空壳 + `app.js` 加载器

**目标**: 产品目录骨架，三种模式共享一个加载器。

**产出**:
- `dist/tang-system/index.html` — 首页导航（阅读 / 观摩 / 练习 三个入口）
- `dist/tang-system/read.html` / `watch.html` / `practice.html` — 各自的壳（此时只有骨架，下一步填内容）
- `dist/tang-system/app.js` — 统一加载器

**app.js 职责**:
1. `fetch('./content.bundle.json')` → `window.TangContent = { chapters, cards, cases, exercises, sources }`
2. 提供检索 API：
   ```js
   TangContent.getChapter(id)
   TangContent.getCardsByChapter(chapterId)
   TangContent.getCasesByChapter(chapterId)
   TangContent.getExercisesByChapter(chapterId)
   TangContent.getCase(id)   // 含 bars
   ```
3. 公开"味儿不对"API：`TangContent.flag(itemId, reason?)` → POST 到本地队列（MVP 用 localStorage，然后手动导出到 `content/flagged/`）

**视觉规范**: 按 `个人设计语言规范.md`。
- 字体：Noto Sans SC + JetBrains Mono
- 配色：`#FAF9F5` 背景、`#1A1A19` 主文字、`#8B9A6D` 强调
- 8px 网格
- 无 box-shadow / 无渐变

**验收**:
- 打开 `index.html` 能看到三个模式入口，点击跳转到对应页面
- 空 content.bundle.json 情况下 `TangContent.getChapter` 返回 `null` 且不崩
- 设计符合规范（色值对一下）

**估时**: 60 min

### T4 · 案例层拆分

**目标**: 把 `teaching_segments.json` 拆成 `cases/seed_*.json`，补 `source / chapters` 两字段。

**产出**:
- `content/cases/seed_01.json` ~ `seed_16.json`（跳过没有的 12/13）+ `case_16_attempts_01.json`
- `content/cases/_index.json`（轻元信息：id / title / chapters / category / scenario，**不含 bars**）

**关键动作**:
1. 读 `data/processed/teaching_segments.json`
2. 对每个 segment：
   - `source` 字段 = 查 `real_chart_figs.json` 反查（seed_02 → `real_chart_analysis Fig 2`；case_16_attempts_01 → `claude_inference`）

   - 其他字段原封不动
3. `_index.json` 只保留这几个字段做目录：`id / title / chapters / category / scenario / source_interval / date`

**一次性脚本**（可并入 content_build.py 当子命令 `--extract-cases` 或独立写 `tools/extract_cases.py`）。

**验收**:
- 15 个 seed 都成功拆出
- case_16_attempts_01 标记为 `source: "claude_inference"` + `status: "draft"`
- _index.json 可直接被 app.js 消费
- 所有 case 文件能 validate 过 case.schema.json

**估时**: 30 min

### T5 · `ch03.json` 章节搬迁

**目标**: 第 3 章从汤总秘籍 HTML 搬迁到结构化 JSON，**逐字抄**，不改写。

**产出**: `content/chapters/ch03.json`

**关键动作**:
1. 从 `汤总秘籍图文版.html` L285~L445（`<!-- 03 信号A -->` 块）提取所有 `.rule / .warning / .danger / .card / .ex / .dw` 节点
2. 每个节点 → 一个 `section` 对象：
   - `kind` 按 CSS class 映射：`.rule → rule`、`.warning → warning`、`.danger → danger`、`.card → card`、`.ex → example`、`.dw/<svg> → illustration`
   - `body_md` = 提取节点的文本内容（HTML 标签转 markdown）
   - `svg_hint` = 若是 illustration，把完整 `<svg>` 字符串存下来（不改）
   - **所有 section 的 `source` = `tang_doc§3`**，`status = "published"`
3. 填 `linked_*`:
   - `linked_cards`: 从 T6 的 4 个 card id 填入（T5 初版可先空，T6 完成后回填）
   - `linked_cases`: `["seed_01", "seed_02", "seed_03", "seed_04"]`
   - `linked_exercises`: 从 T7 的 3 个 exercise id 填入（同上）

**验收**:
- `content_build.py` 对 ch03.json validate 通过
- body_md 抽样与 HTML 原文肉眼一致（挑 3 个 section 对比）
- `linked_*` 字段里所有 id 在对应 index 中存在（T6/T7 完成后回填再校验）

**估时**: 60 min

### T6 · 4 张 Card 初稿（**需用户 approve**）

**目标**: 写出第一批技术细节卡片，作为 card 格式的样板。

**产出**: `content/cards/card_*.json` × 4

**候选列表**（架构师给出，教练身份定稿）:

| id | title | 挂接章节 | source | 初始 status |
|---|---|---|---|---|
| card_ma10_touch_valid | 怎么算是真正触及 MA10？ | ch03, ch04 | tang_doc§3 | draft（需 approve） |
| card_reject_bounce_too_strong | 反抽绿K太长太强怎么办？ | ch03, ch12 | tang_doc§3 | draft |
| card_barrier_too_close | 离关卡多近算"太近"？ | ch03, ch04, ch07 | claude_inference | draft |
| card_confirm_bar_must_close | 确认K必须完整收完吗？ | ch03, ch09 | tang_doc§3 | draft |

**每张 card 内容要求**:
- `answer_md` — 尽量引原话；Claude 扩写的部分单独用 blockquote 标记
- `gray_zones` — 至少 2 条（"算"、"灰色地带"或"不算"的边界）

**用户审核流程**:
1. 我产出 4 份 draft 文件
2. 用户读一遍，标注：
   - OK → 改 `status: "published"`
   - 删掉（错或没必要）→ 我删
   - 改 → 我按 comment 改
3. 确认通过的 publish 进 ch03 的 `linked_cards`

**验收**:
- 4 份文件能 validate
- 用户确认 ≥ 2 张升为 published（否则说明样板没对味，回炉）

**估时**: 架构师 40 min 产出 + 用户审核循环

### T7 · 3 道 Exercise 初稿（**需用户 approve**）

**目标**: A / B / D 三型各一道，定 tutor_40 话术风格和三档判分基调。

**产出**: `content/exercises/ex_*.json` × 3

| id | kind | 用哪个 case | 核心用意 |
|---|---|---|---|
| ex_ch03_A_01 | A_blind_pred | seed_02（标准 Reject MA10） | 验证"空头排列 + 影线触线 = 做空"判分 |
| ex_ch03_B_01 | B_find_signal | seed_01（Support MA10） | 多头场景找 Support 点，训练眼睛 |
| ex_ch03_D_01 | D_checklist_blank | seed_04（绿色反抽型） | 把汤总八步清单拆成填空，验证"第 N 步卡住"的反馈机制 |

**每道题必须满足**:
- 三档 grade（optimal / reasonable / wrong）全覆盖
- `tutor_40` 每条 ≤ 40 字
- wrong 档必须有 `common_trap` 字段（解释"为什么容易被骗到这里"）
- `source` 明确（链接到对应 Fig 或 tang_doc§X）

**D 型特殊字段**（相对 A/B 加两项）:
```json
"checklist_steps": [
  { "step": 1, "question": "5分钟有趋势吗？", "answer_field": "trend", "correct": "bearish" },
  ...
]
```

**用户审核流程**: 同 T6，重点看 tutor_40 话术的"克制度"和三档解释的覆盖面。

**验收**:
- 3 道题 validate 通过
- 用户对每道题至少 3 个 tutor_40 话术 approve（即"这种话术风格我认可"）
- 若话术被批"太冷/太燥/太教条"，按反馈返工 T7，**不前进到 T10**

**估时**: 教练 60 min 产出 + 用户审核循环

### T10 · `practice.html` 练习模式

**目标**: A/B/D 三型都能跑通，三档判分面板显示 tutor_40。

**功能**:
1. URL `?ex=ex_ch03_A_01` → 读 exercise 文件
2. 加载 linked_case → `engine.loadData(case)` → `engine.setCurrentIndex(exercise.setup.cutoff_bar_index, { playMode: "static" })`（截到 cutoff 不让往后看）
3. 渲染 choices（A 型）/ 画布标注工具（B 型）/ 八步填空（D 型）
4. 用户提交 → 查 exercise.grading → 显示：
   - 颜色：optimal 绿 / reasonable 橙 / wrong 红（用规范里的克制色系）
   - `tutor_40` 大字展示
   - `why_md` 折叠展开
   - wrong 档加显 `common_trap`
   - 右上角始终有"味儿不对"按钮 → 调 `TangContent.flag(exerciseId)`
5. 答完后：`engine.setCurrentIndex(cutoff + reveal_followup_bars)` 揭晓后续几根 K

**验收**:
- 三道题都能完整跑完（截断 → 选择 → 三档反馈 → 播放后续）
- "味儿不对"按钮能写入 localStorage（之后 T12 整理成 `content/flagged/` 格式）
- 三档视觉区分清晰但克制

**估时**: 120 min

### T11 · 用户第一次整体校验（**硬闸门**）

**目标**: 由用户给整套 MVP 一次"味儿对不对"的判决。没过就不进 T12，回炉。

**用户检查清单**:

1. **ch03 文本层面**
   - [ ] 汤总秘籍 §3 的原话完整搬过来了？
   - [ ] 有没有被改写过度、味道变了的段落？
   - [ ] SVG 示意图渲染正确？

2. **Card 层面**
   - [ ] 4 张 card 里哪些可以 published、哪些还要改、哪些删掉？
   - [ ] gray_zones 的边界值（"0.02%"这类数字）是不是 Claude 瞎编的？

3. **Exercise 层面**
   - [ ] 三档 grade 的判断**对不对**？特别是 wrong 档（真的错 vs 只是保守）？
   - [ ] tutor_40 的话术是不是过度自信 / 过度华丽 / 过度空洞？
   - [ ] D 型八步填空的 correct 答案，是不是真的"八步清单"的正确答案？

4. **整体体验**
   - [ ] 三种模式切换自然？
   - [ ] "味儿不对"按钮容易找？
   - [ ] 有没有感觉到"Claude 越权"的地方？

**反馈方式**: 用户在 `content/flagged/` 下加文件；或直接在下次对话里说。

**验收**:
- 用户明确说 "这个方向对，可以继续铺 ch04/ch07/..." → 进 T12
- 否则按反馈回炉 T5/T6/T7/T10 对应条目

**估时**: 依用户反馈
