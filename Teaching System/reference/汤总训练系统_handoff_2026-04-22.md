## 3. ClarityMap（已确认）

### 3.1 系统结构：三层

> **注意**：复盘已有专门开发的版本，本系统**不做复盘**。

- **阅读** — 升级版图文攻略（SVG 示意图 → 真实 K 线回放替换）
- **观摩** — 信号案例库，每个形态配真实实盘片段
- **练习** — ABD 混合形态（见 3.3）

### 3.2 内容双维度（交叉引用）

| 维度 | 粒度 | 性质 | 示例 |
|---|---|---|---|
| 主线章节 | 大 | 有顺序、有叙事 | 汤总16章 + 未来新增章 |
| 技术细节卡片 | 小 | 碎片、横向、无固定归属 | "怎么一眼识别缠绕"、"肥柱该多肥"、"影线长度阈值"、"开盘跳空怎么办" |

**交叉引用关系**：读某章时相关卡片自动串联；写一张新卡片时可挂到 1~N 个章节。

### 3.3 练习形态（ABD 混合，**反教条**）

| 形态 | 学习者动作 | 反馈 |
|---|---|---|
| A · 盲盒预测 | 给一段 K 线截到信号点 → 选"多/空/不做" | 播放后续几根，给判分+解释 |
| B · 找信号标注 | 在完整回放里圈出"这里是 Reject MA10" | 对比答案，评估准确度 |
| D · 八步填空 | 给场景 → 按八步清单逐条答 | 指出卡在第几步 |

**"反教条" 硬约束**：
- 非二元对错，允许灰度
- 给 Why，不给"正确/错误"四个字
- 有"示范灰色地带"和"长得像但不是"的反例
- 解释汤总"为什么这样说"而不是照搬原话

## 4. 成功标准（已确认）

### 维度1 · 扩展成本

- 加一张新技术细节卡片 **≤ 5 分钟**
- 加一道新练习题 **≤ 10 分钟**
- **改数据文件即可，不碰引擎代码**

### 维度2 · 练习质量（反教条判分）

每道练习题至少 **3 档判分**：

| 档位 | 含义 | 导师解释要求 |
|---|---|---|
| optimal | 汤总/用户最推崇的做法 | 说清为什么是最优 |
| reasonable | 也对、但差在哪 | 解释"对"在哪、"差"在哪 |
| wrong | 错在哪 | 加"为什么容易被骗到这里"（common_trap 字段） |

**每档导师一句话 `tutor_40` ≤ 40 字**，强制克制。详细解释放 `why_md`。

## 5. 关键难点：认知校验风险

**用户原话**："我怕你不了解量化交易策略，因为我不懂，所以无法纠正你的错误，导致你错了我也看不懂。"

### 5.1 三层信任隔离

| 层级 | 内容类型 | 信任机制 | 举例 |
|---|---|---|---|
| 事实层 | 可数值验证 | 代码算出来，Claude 改不了 | MA10 是否被触及、K 线红绿、价格 vs MA200 |
| 策略层 | 汤总原话复述 | **必须有 `source` 字段**，能追到原文 | "影线触及实体没穿 = 有效 Support" |
| 判断层 | 灰度、例外、手感 | **默认 draft，用户 approve 才能 publish** | "这里差 0.02 也算触及，因为……" |

### 5.2 五条硬纪律（已落地为 build 校验规则）

1. **每条内容带 `source` 字段**：`tang_doc§X` / `real_chart_analysis Fig Y` / `claude_inference`
2. **`claude_inference` 默认 draft**，不进正式内容池，需用户 approve 才能 publish
3. **`tutor_40` ≤ 40 字**，强制克制。越华丽越危险
4. **"味儿不对"按钮**：练习时一键 flag，进待修清单。不用说清哪错
5. **汤总原话优先于 Claude 总结**——能引用原文就引用，不重写。Claude 只做结构化索引和跨章节串联

### 5.3 Claude 能力边界声明

| 能做对 | 可能做错（必须走 draft） |
|---|---|
| 根据汤总规则判断客观事实（均线关系、K 线形态、数值阈值） | 盯盘手感、灰度判断、老炮的例外 |
| 复述、结构化、交叉引用汤总原文 | 发明汤总没说过的策略衍生 |
| 用代码实现可量化的判分逻辑 | 评判"肥柱到底多肥才叫肥"这类经验值 |

## 6. 架构档位

**C 档 · 系统化成长**（正式内容管理体系）

**理由**：
- 内容不是固定 16 章，是持续演化的知识库
- 用户会持续补充"盯盘的技术细节"（不只是 case）
- 需要主线章节 + 技术细节卡片两套索引

**含义**：
- 内容必须数据化（JSON/YAML），不能硬编码在 HTML
- 需要 draft / publish 状态管理
- 需要分目录 + 索引 + tag

## 9. DesignBlueprint v0.1（阶段4 · 2026-04-22 定）

### 9.1 四类对象 Schema

#### 9.1.1 Chapter · 主线章节

```json
{
  "id": "ch03",
  "order": 3,
  "title": "进场信号A — Reject / Support MA10",
  "subtitle": "日常主力信号",
  "source": "tang_doc§3",
  "status": "published",

  "intro_md": "短引文",
  "sections": [
    {
      "id": "ch03.rule.01",
      "kind": "rule | warning | danger | ok | example | illustration | checklist",
      "source": "tang_doc§3 | claude_inference",
      "status": "published | draft",
      "body_md": "正文",
      "svg_hint": null
    }
  ],

  "linked_cards":     ["card_ma10_touch_valid", "card_reject_bounce_too_strong"],
  "linked_cases":     ["seed_01", "seed_02", "seed_03", "seed_04"],
  "linked_exercises": ["ex_ch03_A_01", "ex_ch03_B_01", "ex_ch03_D_01"]
}
```

#### 9.1.2 Card · 技术细节卡片

```json
{
  "id": "card_ma10_touch_valid",
  "title": "怎么算是真正触及 MA10？",
  "question": "影线几乎碰到 MA10，算不算？",
  "source": "tang_doc§3 | real_chart_analysis Fig 2 | claude_inference",
  "status": "published | draft",

  "answer_md": "主回答。汤总原话优先；Claude 改写必须标 claude_inference + draft",

  "gray_zones": [
    { "case": "影线距离 < 0.02%",         "verdict": "算",       "reason": "…" },
    { "case": "影线距离 0.02%~0.05%",     "verdict": "灰色地带", "reason": "…" }
  ],
  "counter_examples": [
    { "case": "长得像但不是的形态", "why": "…" }
  ],

  "chapters": ["ch03", "ch04"],
  "tags":     ["ma10", "信号A", "有效性判断"]
}
```

#### 9.1.3 Case · 观摩案例

**复用现有 segment 结构**，只补两字段：

```json
{
  "id": "seed_02",
  "source": "real_chart_analysis Fig 2",
  "chapters": ["ch03"],
  "...": "其余字段保持 teaching_segments.json 现有结构不变"
}
```

存储拆分：`cases/_index.json`（轻元信息列表）+ `cases/{id}.json`（含 bars，按需加载）。

#### 9.1.4 Exercise · 练习题（A / B / D 三型）

```json
{
  "id": "ex_ch03_A_01",
  "kind": "A_blind_pred | B_find_signal | D_checklist_blank",
  "chapter": "ch03",
  "linked_case": "seed_02",
  "source": "real_chart_analysis Fig 2",
  "status": "published | draft",

  "setup": {
    "case_id": "seed_02",
    "cutoff_bar_index": 31,
    "timeframe_default": "1m",
    "prompt": "看完这 30 根 K，你会："
  },

  "choices": [
    { "id": "short", "label": "做空" },
    { "id": "long",  "label": "做多" },
    { "id": "skip",  "label": "不做" }
  ],

  "grading": [
    {
      "choice_id": "short",
      "grade": "optimal",
      "tutor_40": "空头排列+影线触MA10不穿体，信号干净。",
      "why_md": "详细展开",
      "source": "tang_doc§3"
    },
    {
      "choice_id": "skip",
      "grade": "reasonable",
      "tutor_40": "谨慎可以，但错过标准信号得分不足。",
      "why_md": "…"
    },
    {
      "choice_id": "long",
      "grade": "wrong",
      "tutor_40": "空头趋势里做多，是典型接刀子。",
      "why_md": "…",
      "common_trap": "看到一根绿K就误判反转。"
    }
  ],

  "reveal_followup_bars": 10,
  "tags": ["reject_ma10", "空头"]
}
```

**三档强制**：每道题 `grading` 必须覆盖 `optimal / reasonable / wrong`，build 时缺档报错。

### 9.4 内容工作流

**MVP 阶段：直接编 JSON + schema 校验。**

- **写**: 按模板填 JSON。缺字段、`tutor_40` 超长、缺三档 grading → build 报错
- **发布**: `python tools/content_build.py` → 产 `dist/tang-system/content.bundle.json`（拆后合，单文件加载提速）
- **Draft 保留**: `status: "draft"` 的条目不进产品展示池；产品界面看不见，但 bundle 里保留（方便审批切换）
- **"味儿不对"按钮**: 产品 UI 上一键 flag → 写入 `content/flagged/` 队列 → 下次 build 时把该条目 status 降级为 draft
- **原话优先**: `sections[].source = tang_doc§X` 的段落，body_md **直接抄汤总秘籍 HTML 的文本节点**，不做改写

后续内容量起来了再考虑 Markdown 编译或 web 编辑器——不在 MVP 范围。

### 9.5 认知校验防线 · 落地点

| 硬纪律 | 落位 |
|---|---|
| 每条带 source | JSON Schema 必填字段 |
| claude_inference 默认 draft | `content_build.py` 校验：source=claude_inference 且 status=published → fail |
| tutor_40 ≤ 40 字 | `content_build.py` 校验 |
| 三档 grade 覆盖 | `content_build.py` 校验：exercise.grading 必须包含 optimal/reasonable/wrong 各至少一条 |
| "味儿不对"按钮 | 产品 UI + `content/flagged/` 队列 + build 时降级 |
| 原话优先 | sections[].source=tang_doc§X 的段落 body_md 与 HTML 原文一致（可加 diff 校验作为 stretch） |
